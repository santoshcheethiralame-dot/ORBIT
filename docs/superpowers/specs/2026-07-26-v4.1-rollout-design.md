# Orbit v4.1 rollout — design & runbook

**Date:** 2026-07-26
**Audience:** ~20 known users (friends/classmates), some with the PWA installed
**Update model:** silent auto-reload (no prompt)
**Verification:** Vercel preview → manual verification → promote

---

## Why this release needs a plan

Three things make it riskier than a normal deploy:

1. **It carries a security fix.** The deployed `reminder-cron` function currently
   accepts an unauthenticated `POST {"test":true}` and pushes to *every*
   subscription in the database.
2. **It adds a CSP.** A wrong directive breaks the app for everyone, and the
   service worker makes that state sticky on installed devices.
3. **It changes the cloud-sync fingerprint**, which without migration would show
   every synced user a "pick a copy to destroy" conflict.

## Ordering hazards (both counterintuitive)

### The Edge Function must deploy BEFORE the client

The new client calls `sendTestPush` with `{test: true}` and no `user_id` — the
uid now comes from the verified JWT. The **old** deployed function reads
`body.user_id`, gets `undefined`, and its `sendTest(undefined)` selects every
push subscription in the database.

Deploying the client first would actively fire the mass-notification bug this
release fixes, at every user at once.

### This deploy cannot use its own update mechanism

The auto-reload added here only exists in clients that already have it.
Currently-installed clients run `skipWaiting()` with no reload listener, so on
this deploy their SW swaps while their page keeps running the old bundle. The
`lazyWithReload` wrapper (below) is what makes that transition survivable; it is
the reason this release is safe for people already running v4.0.

## Changes made for the rollout

### A. `lazyWithReload` — survive a deploy that lands mid-session

`index.tsx`. The SW calls `skipWaiting()` + `clientsClaim()` and
`cleanupOutdatedCaches()` purges the old precache, so a live tab running the
previous bundle asks for chunk filenames that no longer exist. With 16
code-split chunks (Courses, Stats, Settings, FocusSession, Onboarding…) almost
every view is exposed.

A failed chunk import now means "you are running a stale build" and triggers one
reload, guarded by a `sessionStorage` flag so a genuinely broken deploy shows the
error boundary instead of reload-looping.

### B. Auto-reload on service-worker takeover

`index.tsx`. A `controllerchange` listener reloads the page.

The guard matters: if the document was **not** controlled at load, the first
`controllerchange` is just the initial registration claiming a first-time
visitor — reloading there would bounce every new user once. Only reload when
`navigator.serviceWorker.controller` was already set at load.

Because the reload is silent, anything losable had to be made durable:

| State | How it survives |
|---|---|
| Focus timer | `utils/focusTimer.ts` → localStorage, wall-clock anchors |
| Active focus block | `orbit-active-focus` |
| Session notes | now persisted on change (debounced), not only on unmount |
| Onboarding draft | `orbit-onboarding-draft` in sessionStorage |
| Daily-context modal | **not** persisted — cheap to redo, accepted loss |

### C. Cloud-sync fingerprint migration

`utils/cloudSnapshot.ts`, `utils/cloudSync.ts`. The fingerprint moved from a
32-bit djb2 to SHA-256 (a djb2 collision is silent data loss — the engine
concludes "nothing changed" and never pushes the edit).

Every already-synced user has an ancestor hash stored in the old format.
Unmigrated, `reconcile` would find that neither side matches the ancestor,
declare a conflict, and ask them to choose which copy to replace — real data
loss for anyone syncing phone + laptop.

`snapshotFingerprint()` returns both formats from one serialisation. An ancestor
matching under **either** algorithm counts as unchanged and is quietly rewritten
in the new format. No prompt, no risk.

## Verification performed locally

Against a real production build (`vite preview`, port 4173):

- SW registers and controls the page; **no** spurious reload on first install
- Published a second build → `registration.update()` → page auto-reloaded and
  came back on the new chunk (`index-hO5T6MQX` → `index-BwQ7aXIV`), app working,
  `sessionStorage` preserved

**Limitation:** `vite preview` does not apply `vercel.json` headers — confirmed,
no CSP header is served locally. The CSP is therefore **unverified** until it
runs on a Vercel preview deployment. This is the main reason for the preview
step below.

## Runbook

### 0. Rotate the OpenRouter key — independent, do first

`.env` was committed in `12546ad`; the key is public in git history and must be
treated as compromised. Untracking it does not undo exposure.

Rotate at openrouter.ai, then re-enter the new key in **Settings → AI Assistant**
on each device (the app reads it from localStorage; it is never bundled).

### 1. Deploy the Edge Function — BEFORE the client

```bash
supabase functions deploy reminder-cron --no-verify-jwt
```

Verify it now rejects unauthenticated calls:

```bash
curl -si -X POST https://tcnaiawfwdfvmdagqpai.functions.supabase.co/reminder-cron \
  -H 'Content-Type: application/json' -d '{"test":true}' | head -1
```

Expect **401**. If this returns 200, stop — the old function is still live and
deploying the client would push to every user.

Old clients keep working (supabase-js attaches their JWT), so there is no window
where existing users are broken.

### 2. Push the branch and open a Vercel preview

### 3. Verify on the preview URL

CSP — the unverified part, check first:

- [ ] DevTools console shows **no** `Content-Security-Policy` violations
- [ ] Fonts load (Google Fonts allowed)
- [ ] Sign-in reaches GitHub (Supabase auth origin allowed)
- [ ] Cloud sync round-trips (REST + `wss` allowed)
- [ ] AI assistant responds (openrouter.ai allowed)
- [ ] PDF resource opens (cdnjs pdf.js allowed)

Then the behaviour changes:

- [ ] Fresh onboarding completes; Unicode subject names accepted
- [ ] Focus: pause holds; reload mid-session restores timer **and** notes
- [ ] Day rollover does **not** re-trigger onboarding
  (set `orbit_last_check_date` to yesterday, reload)
- [ ] Import an **old** v4.0 backup file — exams and settings restore
- [ ] Signed-in sync produces **no** conflict prompt (the C migration)
- [ ] Offline: reload with network off still boots

### 4. Promote to production

### 5. Post-deploy

- Refresh your own phone first and confirm before telling anyone
- Existing tabs will reload themselves via `lazyWithReload`; installed PWAs
  update on next launch
- Then message the group

## Rollback

Redeploy the previous Vercel deployment. From this release onward clients
auto-reload, so rollback is self-healing.

**Asymmetry worth knowing:** rolling back *this* release is the awkward one —
current clients have no reload listener and would need the app fully closed and
reopened. That asymmetry is the main argument for not skipping step 3.

## Known behaviour changes to mention if asked

- **Timezone:** "today" moves from hardcoded Asia/Kolkata to device-local. A
  no-op in India; a classmate abroad will see date-keyed data shift by a day.
- **Notifications:** a user with permission granted but the toggle saved off now
  correctly stays off. Previously it was force-enabled on every load, so this
  may read as "notifications stopped working".

## Not addressed

No tests and no CI. Every claim above is hand-verified in a browser, which is
exactly the coverage that rots. `utils/focusTimer.ts` is now a pure reducer and
is the highest-value place to start.
